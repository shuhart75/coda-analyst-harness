# Запрос создания задачи на принимающей стороне

`analysis-task-request.json` в корне поставки сохраняет явное поручение аналитика создать задачу на принимающей стороне. Это транспортные метаданные, не связь с готовой задачей и не разрешение обойти проверку коммитов.

Поля схемы 1: schema_version=1, request_id (постоянный UUID), provider=sbertrek, target=receiver, role=AN, delivery (ключ зарегистрированной поставки), summary и confirmation (цитата поручения). Поле key отсутствует. Значение role=AN описывает историческое поручение; вид задачи коммита определяется действующим договором: для поставки kind=delivery, suit=task, префикс [SA][PR]. Не создавать отдельную общую задачу AN вместо задачи в эпике поставки.

## Продолжение «синкани репы»

1. Sync проверяет задачи по будущему дереву слияния и при `awaiting-analysis-task` возвращает `task_requests` затронутых поставок вместе с `resolve-commit-task`. Обычная main не меняется. При повторном запуске сохраняются тот же импорт и идентификатор запроса.
2. Обработай поручение по `core/commit-task-resolution.md`: сначала config-status, затем текущие возможности MCP, подтверждённый владелец и эпик, поиск подходящей задачи и при отсутствии создание. Известный эпик не требует ручного номера задачи от аналитика. Неизвестный эпик нужно уточнить; не выводить его из названия или текущего квартала.
3. Используй штатный `commit-taskctl.py` и тот же файл продолжения для сочетания владельца и вида работы. request_id помогает связать поручение с этой работой, но не заменяет поиск по виду работы, точному названию и эпику. После неизвестного исхода создания выполняй сверку по действующему протоколу, без автоматического повторного создания. Новый идентификатор запроса не разрешает завести дубликат для того же владельца.
4. Сохрани проверенную связь схемы 2 в `task_decisions_file` текущего импорта с точными source_commit и base_commit. Если в файле уже есть решения других владельцев, сохрани их. Не пиши связь старой схемы 1. Не редактируй обычную main или bare source.
5. Повтори sync. Он проверит связи, включит их в тот же импорт и отправит ветку для человеческого принятия. Обратная заплата вернёт metadata в source после принятия. До него не объявляй синхронизацию завершённой.

Запрос не разрешает публикацию требований в разработку без реальной задачи. Внешние вызовы выполняет агент по штатному договору и доступным средствам, а не программа синхронизации. Недоступность MCP остаётся видимым блокером. Само наличие произвольного текста в source не заменяет поручение аналитика.
