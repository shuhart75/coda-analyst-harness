# Исключение плановой функциональности из прогноза квартала

## Когда применять

Только по явному подтверждению аналитика: функциональность остаётся в исходном
плане квартала, но не входит в текущий прогноз его выполнения. Отмена или новый
квартал могут оставаться нерешёнными. Не назначай их автоматически.

Этот режим предназначен для плановой функциональности, ещё не подключённой к
execution: без карты актуализации, execution-артефактов (включая корневой
`execution-context.md`) и отдельного
`includes/actual-progress/FEATURE-<slug>.puml`. При наличии любого из этих
источников генератор остановится. Не удаляй источники ради прохождения проверки.
Исключение начатой или уже актуализированной функциональности требует отдельного
решения о сохранении её фактов и этим режимом не поддерживается.

## Формат

Решение аналитика хранится в существующем Markdown-контексте функциональности.
Машинная запись находится в
`planning/<quarter>/gantt/actual-progress-features.json`, рядом с отображением
имён функциональностей. Для исключений используется `schema_version: 2`:

```json
{
  "schema_version": 2,
  "features": {
    "planning-slug": "execution-slug"
  },
  "forecast_exclusions": {
    "planned-feature": {
      "state": "outside-quarter",
      "analyst_confirmed": true,
      "reason": "В прогноз квартала не входит; дальнейший срок не решён.",
      "source": "features/planned-feature/planning/planning-context.md"
    }
  }
}
```

Пример содержит условные имена. Не создавай его как действующую конфигурацию без
решения аналитика. Сохрани существующий объект `features`; если отображений нет,
используй `{}`.

- Ключ исключения — slug планового include, до применения отображения `features`.
- `outside-quarter` относится только к кварталу каталога конфигурации. Это не
  статус отмены и не назначение следующего квартала.
- `analyst_confirmed: true` записывается только после явного подтверждения.
- `reason` — непустая однострочная причина, без выдуманных дат.
- `source` — относительный путь к существующему непустому документу внутри
  аналитического проекта. Генератор проверяет путь, но не доказывает смысл
  документа: агент обязан сверить запись с ответом аналитика.
- Неизвестные поля, состояния, повторяющиеся ключи и неполное решение блокируют
  генерацию до записи.
- Формат версии 1 с объектом `features` продолжает поддерживаться без исключений.
  Старый harness не понимает версию 2 и остановится; обнови его, не понижай схему.

## Генерация и защита данных

Запусти из `HARNESS_ROOT`:

```bash
python3 scripts/sync-quarter-gantt.py "$PROJECT_ROOT/planning/<quarter>/gantt" --actual-only
```

Генератор берёт существующий `FEATURE-<slug>.puml` из `commander-plan`, а если
его нет — из `quarter-plan`. Пустой существующий файл не заменяется другим
источником. Отсутствие обоих файлов блокирует запуск.

В `actual-progress` исходный include показывается без изменения его полос в
разделе `PLAN; вне прогноза <quarter>`. Это только исходный план, не текущие сроки.
Причина и ссылка на решение записываются в комментариях. Тот же раздел входит
в раскрытый экспорт Confluence. Даты, проценты, ресурсы, задачи и
`actualization.md` для исключённой функциональности не создаются; её работа не
попадает в планировщик текущих задач.

Утверждённые планы, их include-файлы, исходные Markdown и снимки не меняются.
Даже при отсутствии карты запись о ней в утверждённом снимке блокирует исключение:
решение о прогнозе не разрешает потерю baseline. Отдельный существующий
actual-progress include также нельзя скрыть этим решением.

Для остальных выбранных функциональностей все прежние проверки источников
сохраняются. Без явного исключения отсутствующая карта остаётся ошибкой.
Удаление решения возвращает обычную проверку карты; возобновление работ не
создаёт факты автоматически. Прямой запуск генератора overlays применяет те же
проверки, но корневое представление и Confluence обновляет только команда квартала.

Произвольные ручные блоки `FORECAST-*.puml` и preamble не являются реестром
исключений. Проверь, не содержат ли они отдельный устаревший прогноз той же
функциональности; не приписывай такую связь по похожему названию и не удаляй
блок автоматически. При противоречии покажи источник и остановись до решения.

После запуска проверь diff, неизменность планов и соответствие экспорта штатному
`expand-plantuml-includes.py`. Ошибки останавливают публикацию; обычная ошибка
записи откатывает уже записанные файлы. Коммит, submit и слияние требуют отдельного
разрешения.
