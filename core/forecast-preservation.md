# Сохранение существующего прогнозного блока

## Назначение

Используй этот режим, когда аналитик явно решил оставить существующие
FORECAST-полосы без изменения. Это не исключение из квартала, не подтверждение
старых дат заново, не факт реализации и не решение о переносе или отмене.

Режим применяется к плановой функциональности без `planning/actualization.md`,
execution-источников (включая корневой `execution-context.md`) и отдельного
`includes/actual-progress/FEATURE-<slug>.puml`. Он не разрешает скрывать
существующие факты или потерю утверждённой карты. При появлении таких источников
генерация останавливается: нужна отдельная согласованная актуализация.

## Запись решения

Прочитай существующий блок и документ с решением аналитика. Зафиксируй решение
в Markdown-контексте, а машинную запись добавь в
`planning/<quarter>/gantt/actual-progress-features.json`. Используй
`schema_version: 3`, сохрани существующий объект `features` и остальные решения.

Условный пример; имена, путь, aliases и контрольную сумму возьми из проверенных
источников, не копируй заполнители как действующую запись:

```json
{
  "schema_version": 3,
  "features": {},
  "preserved_forecasts": {
    "planned-feature": {
      "state": "preserve-existing",
      "analyst_confirmed": true,
      "reason": "Существующие полосы сохраняются без повторного подтверждения дат.",
      "source": "features/planned-feature/planning/planning-context.md",
      "include": "includes/actual-progress/FORECAST-existing.puml",
      "sha256": "<64 строчных шестнадцатеричных символа SHA-256 файла>",
      "aliases": ["FORECAST_EXAMPLE_BE", "FORECAST_EXAMPLE_FE", "FORECAST_EXAMPLE_QA"]
    }
  }
}
```

- Ключ — slug планового include до применения отображения `features`.
- `source` — существующий непустой документ внутри аналитического проекта.
  Агент сверяет его смысл с ответом аналитика; проверка пути не доказывает согласие.
- `analyst_confirmed: true` требует явного решения о сохранении.
- `reason` — непустая однострочная причина.
- `include` — относительный путь от каталога Ганта к существующему
  `includes/actual-progress/FORECAST-<name>.puml` этого квартала.
  Символические ссылки и выход за этот каталог не поддерживаются.
- `sha256` — контрольная сумма точных байтов всего файла, включая окончания строк.
  Агент вычисляет её автоматически: `shasum -a 256 <file>` на macOS или
  `sha256sum <file>` на Linux. У аналитика не нужно запрашивать хеш.
- `aliases` — непустой уникальный список явно связанных с функциональностью
  идентификаторов полос `FORECAST_*`. Каждая должна быть объявлена в файле ровно
  один раз. Сходство названий не устанавливает эту связь.
- Один общий файл может содержать другие функциональности и фактические полосы:
  сохраняется весь файл, а не извлечённый фрагмент. Это не отменяет проверки
  источников остальных выбранных функциональностей. Для нескольких решений по
  одному файлу списки aliases не должны пересекаться.
- Для одной функциональности нельзя одновременно задать `preserved_forecasts`
  и `forecast_exclusions`. Сохранение нельзя подменять `outside-quarter`.
- Старые форматы 1 и 2 остаются поддержанными для прежних операций. Старый harness
  не понимает формат 3 и должен остановиться; не понижай схему ради обхода.

## Границы сохранения

Сохраняемый файл должен быть уже подключён в существующий `actual-progress.puml`
ровно один раз, непосредственно или через include-цепочку. Новый неподключённый
файл этот режим не включает автоматически.

Поддерживается конечный FORECAST-файл без директив препроцессора и собственных
границ диаграммы `@startgantt` / `@endgantt`. Родительские
preamble могут содержать вложенные includes: граф обходится штатным
`expand-plantuml-includes.py`. Условия, макросы и вложенные includes внутри
самого сохраняемого файла требуют отдельного решения; не разворачивай и не
переписывай их автоматически ради прохождения проверки.

Исходный план берётся из существующего commander include, либо quarter include,
если commander отсутствует. Он показывается отдельно как `PLAN` без переноса
дат и без создания истории или карты. Обе исходные плановые диаграммы и их
include-файлы остаются неизменными при запуске `--actual-only`.

Сохраняемый FORECAST-файл не записывается генератором и не участвует в
перерасчёте дат или загрузки ресурсов. Его ресурсные линии и проценты остаются
содержимым прежнего прогноза, а не новыми подтверждёнными фактами. Режим не
обещает согласованную загрузку между старым блоком и пересчитанными задачами.

Подключение сохраняется ровно один раз: если оно уже идёт через preamble,
второе не добавляется; иначе файл подключается после сгенерированных разделов
функциональностей. Положение самих полос внутри файла не меняется. Причина и
источник решения добавляются только в комментарии корневого Ганта.
Confluence содержит раскрытый блок с теми же полосами.

## Проверки и запуск

Перед записью проверяются подтверждение и источник решения, контрольная сумма,
наличие объявленных aliases и отсутствие потери execution-источников или
утверждённого baseline. Повторные идентификаторы между сохранённым блоком и
остальным Гантом блокируют публикацию. Потеря другого прежнего FORECAST-подключения
также блокирует её: агент показывает источник и запрашивает решение, не удаляет
и не подключает посторонние файлы автоматически.

Изменение общего файла делает контрольную сумму устаревшей. Покажи точный diff
и проверь полномочия на изменение; не обновляй хеш вслепую. Исчезновение файла
или решения не превращается в молчаливый пропуск функциональности.

Из `HARNESS_ROOT` запускай:

```bash
python3 scripts/sync-quarter-gantt.py "$PROJECT_ROOT/planning/<quarter>/gantt" --actual-only
```

Прямой генератор overlays проверяет запись сохранения, исходное подключение и
целостность файла, но только квартальная команда проверяет итоговые подключения
и коллизии идентификаторов, пересобирает корневой Гант и Confluence.
После запуска проверь исходные байты файла, его единственное
подключение, неизменность планов и точное соответствие Confluence штатному
раскрытию includes. При ошибке запись не начинается; обычная ошибка записи
откатывает уже записанные результаты, без обещания crash-atomic транзакции.

Проектные документы не меняются при обновлении harness. Применение записи в
аналитическом репозитории, коммит, submit и слияние — отдельные действия.
