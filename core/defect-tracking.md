# Дефекты в прогнозе и квартальной статистике

Дефект определяется исходным `suit="bug"`, а не префиксом заголовка. Чтение,
принадлежность поставке, история и применение проходят обычные tracker gates.
Не меняй прежние raw-ответы и завершённые обзоры истории для нового правила.

## Отбор и применение

Собирай дефекты в подтверждённой области задач, эпиков или релиза. Для полного
квартального показателя отдельно согласуй область сбора назначений за квартал:
один релиз не доказывает полноту всех дефектов разработчика. Текущий исполнитель
может уже быть тестировщиком, поэтому используй историю назначений.

Каноническая роль дефекта берётся из подтверждённого разработчика, а не заголовка.
Если роль или владелец неизвестны, они требуют подтверждения в обычной сверке.
Уже сохранённая роль не меняется молча при передаче между разработчиками.
Регистрируй дефект как `Kind=real`, `Suit=bug`, с одним `Task ID`, ключом SberTrek,
ролью BE/FE и подтверждённым ресурсом разработчика в `Executor`. Сохраняй источник
назначения в Notes. При передаче в QA сохраняй атрибуцию разработчика отдельно
от текущего исполнителя карточки. Даты и прогресс вычисляй по
`core/tracker-lifecycle.md`; отсутствие оценки не означает ноль или один день.

`history-review` сохраняет `defect_assignments` из исходной истории. Повторное
назначение одному разработчику не увеличивает число уникальных дефектов квартала.
Назначение без даты сохраняется как неизвестное по периоду, без придуманной даты.

## Представления

Дефекты включаются только в `actual-progress-estimates-only.puml` и его
Confluence-экспорт. Их трудоёмкость занимает ресурс в этом прогнозе, коэффициент
равен единице. Обычный actual-progress, focus, quarter-plan и commander-plan
не получают ни полос дефектов, ни их резервирования ресурсов.

Дефекты не входят в знаменатель распределения QA обычных FE/BE-работ и не создают
новые остаточные QA-группы. Они не продлевают прогноз QA фичи автоматически.
Неизвестная оценка незавершённого дефекта блокирует генерацию estimates-only;
успешный расчёт остальных представлений не разрешает частичную запись квартала.
Для завершённого дефекта разрешены уже поддерживаемые фактический интервал и
отметка завершения без выдуманной оценки.

## Итоги квартала

В отчёте команды обязателен показатель «Дефекты, назначенные разработчику»:
число уникальных ключей bug, назначенных этому человеку в квартале. Отдельно
покажи ключи, неопределённые даты и полноту сбора. Для одного человека повторные
назначения одного ключа считаются один раз; при назначении разным людям ключ
попадает в показатель каждого, поэтому суммы по людям могут превышать число багов.
Назначение не доказывает авторство ошибки и не вычитается из выпуска автоматически.

Для воспроизводимого расчёта по завершённым обзорам истории:

```sh
python3 scripts/defect_metrics.py --quarter 2026-Q4 --review PATH_TO_HISTORY_REVIEW.json
```

Повторяй `--review` для нескольких обзоров. Скрипт выводит JSON в stdout и
не изменяет аналитику. Часовой пояс по умолчанию `Europe/Moscow`, при необходимости
задаётся `--timezone`. Сохраняй результат, контрольные суммы источников и границы
выборки вместе с квартальным отчётом через обычный процесс сохранения аналитики.
Без подтверждённой полноты подписывай показатель как наблюдаемый минимум.
