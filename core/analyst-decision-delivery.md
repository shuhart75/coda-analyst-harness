# Передача по решению аналитика

Этот маршрут имеет приоритет над обычным циклом передачи, когда аналитик явно
просит передать текущий пакет по своему решению, без аудита и сверки с кодом.
Сам запрос «передай» без такого уточнения сохраняет обычный маршрут.
Не предлагай аудит, восстановление main, record-change или отмену старой передачи
как предварительные условия этого режима. Полученное разрешение не переспрашивай.

Одна команда из корня обвязки:

```sh
python3 scripts/requirements-exchange.py send-by-decision PROJECT_ROOT DELIVERY_KEY \
  --reason 'Точная формулировка решения аналитика' --analyst-confirmed
```

Пути и ключ поставки разреши из конфигурации. Если репозиторий кода не настроен,
укажи `--code-root PATH`; целевую ветку при необходимости — `--target-branch BRANCH`.
Не угадывай адрес получателя. `--analyst` необязателен: используется текущая
идентичность, а при её отсутствии нейтральное `analyst` без дополнительного диалога.
Решение и пропущенные проверки записываются в `delivery_decision` редакции.

Команда берёт рабочие байты requirements.md, sdd/ и materials/ без переписывания.
Она не требует принятой main, чистого дерева аналитики, подтверждённого аудита,
актуальных пинов, правильной трассировки и актуального materials/SHA256SUMS.
Все эти проверки имеют отметку `not-performed`. Контрольные суммы автоматически
вычисляются по реальным файлам исключительно для идентичности транспорта.
Решение не объявляет пропущенные проверки успешными и не меняет запись аудита.

Номер новой редакции определяется автоматически. Незавершённые кандидаты не
блокируют отправку: их оригинальные записи, старые ветки и локальные снимки
сохраняются; новая передача содержит сведения о замене, реестр — отдельную ссылку
`replacement_by_decision`. Старые квитанции не переносятся. Отменять старого
кандидата отдельной командой не требуется. Человек закрывает его PR без слияния.
В целевой ветке сохраняются все прежние файлы редакций; их состояние может стать
`superseded`. Содержимое старых редакций не заменяется текущими байтами.

Если этап уже зарегистрирован, сохраняется его идентичность без сверки текста.
При первой передаче без этапов инструмент создаёт техническую запись stage-1
с названием из заголовка требований; это учёт отправки, не новое согласование
или расширение бизнес-объёма. Закрытие этапа и внедрение не выполняются.

Команда изменяет только новый каталог редакции, управляемый договор обмена и
локальный учёт передачи. Обычный клон кода остаётся неизменным. Публикация идёт
только в отдельную ветку requirements/decision/**, целевую ветку принимает человек.
Файловые ссылки, выход из каталогов, повреждение снимка и перезапись чужих файлов
не разрешаются решением об отказе от аудита. Недоступный Git остаётся технической
ошибкой; обвязка не объявляет локальную копию доставленной в разработку.

После слияния повтори **ту же команду**: она проверит размещение точных байтов
и сама зарегистрирует публикацию. `prepare`, новый аудит и `mark-published`
для этого маршрута не нужны. Повтор после обрыва сети также использует тот же
номер, снимок и коммит. Служебные данные лежат в `.workspace-state/decision-transfers/`;
не удаляй их до завершения передачи. Пути разрешаются в физические абсолютные
каталоги, поэтому отдельная настройка TMPDIR на macOS не нужна.

## Получатель

В поставляемом sdd-receive.py режим распознаётся по связанному с редакцией
`delivery_decision`. Выполни обычный dry-run, затем `--apply` в разработческой
сессии, когда приём разрешён пользователем. Не запускай verify_sources, повторный
аналитический аудит или OpenSpec validate как условия приёма этого пакета.
Устаревший SHA256SUMS из материалов остаётся историческим содержимым, а точность
транспорта определяется инвентарём sdd_input. Старые версии получателя должны
отказать на новом дескрипторе; используется получатель из новой ветки передачи.

Для решения аналитика приём создаёт отдельный change с суффиксом редакции и хеша,
сохраняя исходные proposal/spec и прежние design/tasks. Используй путь и команды,
которые вернул получатель. Отметка source.status=not-performed честно показывает,
что совместимость с кодом не проверялась. Запиши квитанцию точной редакции и
продолжай разработческую работу; выявленные расхождения обсуждай по существу,
не возвращай пакет аналитику только ради аудита или обновления пинов.

Структура адреса импорта (package.json, changes, target_root, change_id) должна
позволять понять, куда безопасно положить файлы. Если она нечитаема или указывает
за пределы рабочей копии, получатель сообщает конкретную техническую ошибку.
Приём не означает успешной сборки, реализации, бизнес-приёмки или внедрения.
