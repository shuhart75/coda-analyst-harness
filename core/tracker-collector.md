# Контракт прямого tracker-вызова

`direct-tracker-v1` не использует субагентов. Основной агент выполняет один
машинно заданный шаг за раз.

## Единственный источник следующего действия

После `begin`, `ingest` или `run-status` используй только объект `next_action`:

- `provider` определяет трекер;
- `tool` определяет MCP-операцию;
- `arguments` передаются без изменения;
- `step_id` связывает полный ответ с точным этапом;
- `ingest_command` является единственной командой успешного импорта;
- `error_command` присутствует только там, где допускается подтверждение
  удалённых Jira-counterpart.

Не формируй TQL/JQL, поля, лимит, provider, evidence или следующий этап сам.

## SberTrek

Вызови `issue.exportJson` или одноимённую доступную bulk export операцию с точными
аргументами из `next_action`. Обязательны:

- TQL в `query`, а не в `issue.search.text`;
- `max_results=50`;
- поле `attributes` в проекции;
- один полный JSON-ответ.

Не используй `issue.search`, `issue.getByKey`, `link.list` или выдуманную
пагинацию. Пользовательские атрибуты `assigned_to`, `story_points`, `issue_key`,
ролевые оценки и релизы разбирает `trackerctl.py`.

## Jira

Вызови `jira_search` с точными `jql`, `fields` и `limit=50` из `next_action`.
Явный список полей включает все известные поля оценок `AN / BE / FE / QA` и
общие оценки. Пустые кастомные поля могут отсутствовать в ответе; это не повод
менять запрос или выполнять `jira_get_issue` по одной задаче.

Для эпика используется прямой JQL `"Epic Link" = "KEY"`. Не заменяй его чтением
`issuelinks`, `parent`, текстовым поиском или промежуточным `key IN (...)`.

## Импорт

Предпочитай исходный JSON-файл MCP. Если инструмент вернул полный JSON inline,
дословно сохрани весь ответ во внешний временный файл. Затем выполни
`ingest_command`, заменив только:

- `<full-json-path>` на абсолютный путь;
- `<mcp-file|inline-json-capture>` на фактический источник.

Не создавай внутри tracker-run копию ответа. Не извлекай карточки, не меняй JSON,
не используй preview и не передавай собственный `provider`, query или evidence.
Идентичный повтор безопасен; другой ответ для того же завершённого `step_id`
фатален.

Если Jira counterpart-запрос вернул только явные сообщения об отсутствующих
ключах, сохрани полный ответ и выполни `error_command`. Выполни уменьшенный запрос,
который вернёт программа. Для других ошибок автоматическое продолжение запрещено.

После команды импорта немедленно перейди к новому `next_action`. Не запускай
`begin`, не создавай второй run и не отвечай пользователю фактами карточек до
успешного `result-status`.
