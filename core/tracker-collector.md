# Изолированный сборщик трекера

Этот договор применяется только к субагенту, которому координатор передал один
`collector-job`. Сборщик работает только с указанным провайдером и не принимает
решений об области, сопоставлении задач, выводах или изменении планов.

## Граница контекста

Прочитай только этот файл и переданный JSON job. Не читай `AGENTS.md`,
`core/tracker-reading.md`, документы проекта, спецификацию или документацию MCP.
Не запускай bootstrap и не исследуй репозитории.

Для выбора инструмента просмотри только доступный runtime-каталог MCP и выбери
один инструмент, который умеет выполнить точный TQL/JQL либо прочитать историю
точного ключа. Имя MCP-сервера заранее неизвестно. Не выполняй пробных вызовов и
не подбирай альтернативный синтаксис.

## Collection job

1. Возьми точный запрос из prompt; `query.text` в job должен совпасть с ним. Передай
   этот запрос MCP без изменения единого символа. Не интерпретируй назначение
   запроса и не заменяй его поиском по тексту, названию или смыслу.
2. Если SberTrek MCP поддерживает `fields` или аналогичную проекцию, запроси только
   `response_contract.preferred_fields`. Не передавай `fields=null` и не запрашивай
   все поля карточки. Это уменьшает ответ, но не заменяет проверку полноты.
3. Выполни один поисковый вызов на страницу. Продолжай только реальную пагинацию
   тем же запросом и полученным cursor.
4. Для SberTrek используй полный JSON-файл, созданный самим MCP-инструментом. Не
   открывай его через `read_file`, не анализируй preview и не переписывай увиденные
   элементы вручную: интерфейс может скрыть середину большого ответа. Передай
   исходный путь без копирования в `trackerctl.py ingest-query-response`. Команда
   сама разберёт JSON, вычислит SHA-256, посчитает элементы, зарегистрирует evidence,
   страницу и все компактные карточки. Если MCP не дал полный JSON-файл или импорт
   не поддержал реальную схему, остановись с ошибкой; не создавай сокращённую копию.

   ```bash
   python3 <HARNESS_ROOT>/scripts/trackerctl.py ingest-query-response \
     --run-id <run-id> --provider sbertrek --page-number 1 --last-page \
     --evidence mcp:sbertrek:<unique-call-id> \
     --response-file <absolute-mcp-json-path>
   ```

   Команда сама берёт точный запрос из активного job; не вставляй TQL в shell и
   не пытайся вручную экранировать его кавычки.

   Для следующей реальной страницы передай её cursor, следующий номер и отдельный
   исходный файл; `--last-page` ставь только для последней страницы.
5. Для Jira после каждого вызова сразу запиши evidence через `trackerctl.py mcp-log`,
   затем страницу через `query-page`; для каждого ключа страницы запиши компактную
   карточку через `record-issue`. Используй только данные bulk-ответа. Не вызывай
   detail по каждой задаче.
6. Не сохраняй описание, комментарии, вложения и полный ответ в tracker-run.
7. Для `assignee`, `estimate`, `epic`, `releases` различай `value`, `absent` и
   `not-returned`. Сохрани обязательные `created_at` и `updated_at`.
8. Для SberTrek извлеки Jira key только из атрибута с `code: issue_key` и передай
   `jira_key_state`: `value`, если ключ есть; `absent`, если список атрибутов
   возвращён и такого атрибута нет; `not-returned`, только если MCP не вернул
   атрибуты и наличие связи невозможно установить. Для Jira состояние не нужно.
9. Заверши job командой `collector-complete --run-id ... --provider ...` и сразу
   верни управление координатору. Не выполняй следующий job из ответа команды.

Если исходный запрос недоступен, остановись с ошибкой. Недоступность только
counterpart-провайдера можно зарегистрировать через `query-unavailable` после
реального ошибочного вызова.

## History job

Для каждого ключа из `keys` выполни ровно один вызов истории. После вызова:

1. запиши его через `mcp-log --operation history`;
2. сохрани только события полей `assignee` и `status` через `history-event`;
3. отметь ключ через `history-complete` как `complete` либо `unavailable`;
4. после всех ключей выполни `history-job-complete --job-id ...`.

Не сохраняй историю описания, комментариев, оценок, ссылок или вложений.

## Запрещено

- менять текст точного запроса;
- читать документацию MCP или вызывать capability discovery;
- искать задачи по названию или описанию;
- читать карточки по одной после bulk-запроса;
- вызывать другой трекер;
- создавать скрипты или любые файлы, не предусмотренные job;
- создавать вручную сокращённый JSON вместо полного файла ответа MCP;
- считать задачи по видимому preview, `head`/`tail` или усечённому выводу;
- менять трекеры, требования, планы, Gantt, Git или файлы вне каталога run;
- пересказывать координатору содержимое задач.

## Ответ координатору

Верни только `status`, `job_id`, `run_id` и пути, напечатанные командой завершения.
Не включай таблицу задач, наблюдения или следующий точный запрос.
