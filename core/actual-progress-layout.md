# Состав и приоритеты actual-progress

`planning/<quarter>/gantt/actual-progress-layout.json` фиксирует подтверждённые
аналитиком состав, названия, порядок фич и начало видимой шкалы. Это описание
представления и приоритетов, не новый квартальный план и не реестр фактов.
Перед его использованием обнови harness; старые клиенты не учитывают этот файл.

```json
{
  "schema_version": 1,
  "analyst_confirmed": true,
  "source": "layout-decision.md",
  "project_start": "2026-07-01",
  "sections": [
    {
      "feature": "cohort-simulation",
      "title": "Справочник когорт",
      "include": "includes/actual-progress/FEATURE-cohort-simulation.puml"
    }
  ]
}
```

`source` указывает на непустой документ решения относительно каталога Ганта.
Абсолютные пути, выход из каталога, символические ссылки, повторные ключи JSON,
фичи и названия запрещены. Slug остаётся техническим ID; сопоставление с папкой
задаётся отдельно в `actual-progress-features.json`.

Порядок `sections` идёт от высшего приоритета к низшему. Названия используются
в заголовках и ролевых PLAN. Исходная длительность PLAN не меняется.
Генератор сначала резервирует фактические интервалы, затем внутри каждой роли
распределяет прогнозную работу в порядке приоритета фич. Менее приоритетная работа
может занять свободное окно, только если не задерживает более приоритетную.
Ограничения ресурсов, календаря и зависимостей ролей продолжают действовать.

Для сохранённого прогноза допускается
`includes/actual-progress/FORECAST-<name>.puml`. Несколько соседних разделов могут
ссылаться на один общий файл: он подключается один раз, его названия и порядок
должны точно совпадать с описанием. Требуется существующее подтверждение сохранения
по `core/forecast-preservation.md`; сам файл не переписывается.

Генерация разрешена только через `sync-quarter-gantt.py <gantt> --actual-only`.
Все execution-разделы должны иметь источники. Лишний существующий actual include,
неуказанный FORECAST, повторный раздел в preamble или несовпадение итогового состава
блокируют запись, а не удаляются автоматически. Режим исключений с отдельным
исходным PLAN в этом описании не поддерживается. Без файла сохраняется прежний
способ определения состава и порядка; автоматической миграции нет.

## Текущие и следующая фича

Каждая генерация квартала дополнительно создаёт `actual-progress-focus.puml`
и самостоятельный `actual-progress-focus-confluence.puml`. Новый вид читает
те же execution-источники и выбирает строки уже рассчитанного полного Ганта:
удаление соседей не освобождает ресурсы и не меняет даты.

- Текущими считаются все поставки с начатой незавершённой задачей. Признаки начала:
  фактическая дата, положительный процент меньше 100 или статус работы/тестирования.
  Неизвестный процент QA не исключает её, если начало подтверждено этими признаками.
  Плановая дата и начало рассчитанной QA-полосы сами по себе не означают начало.
- Следующая — ровно одна первая по подтверждённому порядку поставка с оставшимися
  неначатыми задачами и без активных. Ранее завершённые задачи ей не мешают.
  Все текущие выводятся сначала, следующая — после них; при отсутствии кандидата
  лишняя фича не добавляется. Если текущих нет, можно показать только следующую.
- 100%, окончание/граница завершения и завершённый статус исключают задачу из
  активных. Отменённые, заменённые, удалённые задачи и кандидаты не участвуют.
  Пустые и полностью завершённые поставки не становятся «следующими».
- Неподтверждённое состояние начала не подменяется неначатым: такая поставка
  пропускается с диагностикой. Подтверждённый сохранённый FORECAST без фактов
  начала может быть следующей поставкой, но не текущей.
- Подтверждённые записи внедрения скрывают выпущенные задачи, в том числе внутри
  ещё активной поставки. Завершение само по себе не доказывает выпуск; остальные
  завершённые задачи выбранной поставки остаются для контекста.
- Вехи невыпущенных релизов выбранных поставок сохраняются с датами, подписями,
  оформлением и подсветкой дней полного Ганта. Связь определяется по `releases.json`
  и подтверждённому членству задач. Для прежнего формата допустим точный ключ релиза
  в комментарии непосредственно перед вехой в preamble; неоднозначная связь не угадывается.
  Выпущенные и посторонние релизы, общие вехи и отдельный календарь отпусков скрываются.
  Прошедшая дата сама по себе не доказывает выпуск и не исключает плановую веху.
  При пустом отборе старое содержимое заменяется явно пустым видом.

Оба файла сохраняются вместе с полным actual-progress. Проверка сохранения
контролирует наличие пары и точное соответствие Confluence-экспорта исходнику.
