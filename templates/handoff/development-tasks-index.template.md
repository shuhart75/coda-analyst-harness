# Техническая декомпозиция

Функциональность: **<Название>**  
Редакция требований: `<revision>`  
Состояние декомпозиции: **черновик**

## Что делать разработчику

1. Сказать SDD, какой контур нужно декомпозировать. Пути указывать не нужно.
2. Проверить предложенные ниже будущие задачи Jira и открыть нужную карточку: в ней есть полный состав, состояние кода и команды изменения.
3. Короткими командами объединить, разделить, переименовать или изменить карточки.
4. После принятия состава сказать: `Декомпозиция подтверждена разработкой.` Снимок уйдёт аналитику фоново, разработку можно начинать сразу.
5. Для реализации сказать: `Возьми DEV-* в разработку.` SDD сама подготовит и зарегистрирует квитанцию результата.

## Проверка покрытия

- [ ] все требования из `manifest.json` распределены либо явно признаны непокрытыми;
- [ ] все `SCN-*` распределены либо явно признаны непокрытыми;
- [ ] все `IMP-*` распределены либо явно признаны непокрытыми;
- [ ] каждая действующая карточка относится к одному контуру;
- [ ] зависимости не образуют цикл.

## Основные короткие команды

| Команда | Назначение |
|---|---|
| `Подготовь декомпозицию серверной части.` | Исследовать только серверный контур и предложить `DEV-BE-*`. |
| `Подготовь декомпозицию клиентской части.` | Исследовать только клиентский контур и предложить `DEV-FE-*`. |
| `Проверь декомпозицию.` | Проверить структуру и покрытие без содержательных изменений. |
| `Покажи непокрытые требования.` | Получить диагностический отчёт без изменения файлов. |
| `Подготовь список для Jira.` | Получить подтверждённые карточки; ключи Jira и оценки необязательны. |
| `Декомпозиция подтверждена разработкой.` | Создать фоновый снимок для аналитика и разрешить сразу продолжить разработку. |

Команды изменения конкретной задачи всегда находятся в её карточке и не удаляются при обновлении.
