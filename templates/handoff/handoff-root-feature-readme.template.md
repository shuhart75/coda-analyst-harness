# Общий пакет функциональности `<package-id>`

Этот каталог является общей рабочей точкой разработчиков, аналитиков и тестировщиков. Для работы разработчику нужны локальный клон `coda` и доступ на чтение и запись к этому каталогу. Копировать аналитический репозиторий или переносить требования в `coda` не нужно.

Формальный договор для SDD находится в `AGENTS.md`. Актуальная редакция и разрешённое действие определяются только файлом `handoff.json`.

## Что должен сделать разработчик

1. Открыть локальный клон `coda` на нужной ветке.
2. Подключить этот каталог пакета к рабочей области SDD как второй каталог с правом записи.
3. Дать команду: `Обработай активную редакцию пакета.`
4. Проверить предложенные карточки будущих задач Jira в `returns/development-tasks/index.md` активной редакции.
5. Уточнять декомпозицию короткими командами из `index.md` и карточек. Пути указывать не нужно.
6. После принятия состава дать команду: `Декомпозиция подтверждена разработкой.`
7. Сразу начать нужную задачу командой: `Возьми DEV-* в разработку.` Ответа аналитика ждать не нужно.
8. После работы убедиться, что SDD зарегистрировала квитанцию результата. Вручную редактировать JSON или переносить файлы аналитику не требуется.

## Основные команды

| Команда | Результат |
|---|---|
| `Обработай активную редакцию пакета.` | Принять разрешённую редакцию и подготовить предлагаемую техническую декомпозицию. |
| `Подготовь декомпозицию серверной части.` | Создать или уточнить карточки `DEV-BE-*`. |
| `Подготовь декомпозицию клиентской части.` | Создать или уточнить карточки `DEV-FE-*`. |
| `Проверь декомпозицию.` | Проверить размеры, зависимости и покрытие. |
| `Покажи непокрытые требования.` | Показать диагностический отчёт без изменения файлов. |
| `Декомпозиция подтверждена разработкой.` | Зафиксировать снимок декомпозиции и передать его аналитику фоново. |
| `Возьми DEV-* в разработку.` | Начать реализацию подтверждённой карточки. |
| `Подготовь список для Jira.` | Показать подтверждённые карточки без изменения Jira. |

Команды объединения, разделения, переноса требований и изменения конкретной задачи находятся в каждой карточке.

## Назначение файлов

- `README.md` — эта памятка разработчику.
- `AGENTS.md` — обязательный формальный договор SDD.
- `handoff.json` — актуальная редакция, состояние и следующее действие.
- `revisions/<revision>/package/` — неизменяемые входные требования.
- `revisions/<revision>/returns/` — карточки и квитанции разработчиков и тестировщиков.
- `.control/` — служебные инструменты и шаблоны, которые вызывает SDD.

## Транспортный ZIP

ZIP не хранится внутри репозитория и не нужен для штатной декомпозиции, регистрации начала работы или возврата квитанций. Только по явному требованию аналитика служебная команда создаёт транспортную копию опубликованной редакции в `~/Downloads`.
