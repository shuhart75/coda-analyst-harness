# Шаблоны требований

## Основной шаблон

`feature-requirements.template.md` — единственный активный шаблон новых и
существенно перерабатываемых требований.

Он задаёт компактную спецификацию функциональности:

- назначение и границы;
- необязательное связное описание процесса и PlantUML;
- правила `REQ-*` в естественном порядке;
- вложенные сценарии с русскими ключевыми словами `Когда` и `Тогда`;
- обязательный раздел влияния на соседние функциональности;
- источники и открытые вопросы.

Текст одновременно следует `core/requirements-wording.md`: количества, ссылки,
начальные состояния, события и результаты указываются явно. Автоматически
распознаваемые дефекты проверяет `scripts/validate-requirements-wording.py`.

`feature-requirements.readable.template.md` сохранён только как указатель для
прежних ссылок и не является вторым шаблоном.

## Источник истины

`features/<feature>/requirements.md` — единственный авторский документ. Обвязка не
формирует срезы, отдельные требования по контурам, предварительные задачи или копии
после каждого изменения.

## Аудит и передача

По явной команде передачи обвязка:

1. проводит трёхуровневый аудит по `core/requirements-audit.md`;
2. выполняет проверку контролируемых формулировок и изолированного читателя;
3. исправляет только однозначные ошибки;
4. задаёт по одному вопросу для каждого предметного сомнения;
5. после исправлений повторяет все три уровня по всему документу;
6. показывает отчёт и запрашивает явное подтверждение;
7. после подтверждения копирует текущий `requirements.md` в неизменяемую редакцию;
8. создаёт или обновляет `manifest.json` и сообщает фактическое место размещения.

Разработческая SDD преобразует бизнес-контракт в собственные технические изменения
по контурам. Форматы манифеста и возвратов находятся в `templates/exchange/`.
