# Шаблоны требований

## Основной шаблон

`feature-requirements.readable.template.md` — единственный активный шаблон для новых и существенно перерабатываемых требований.

Он задаёт последовательный человекочитаемый документ:

- краткое описание, цель и границы;
- текущее и требуемое состояние;
- общую схему PlantUML;
- функциональные главы по ходу процесса;
- правила `REQ-*` внутри соответствующих глав;
- примеры приёмки `AC-*`;
- ошибки, влияния, подчистку хвостов и сводную трассировку.

`feature-requirements.template.md` сохранён только как указатель для старых программ и не является разрешённым форматом новых требований.

## Источник истины

`features/<feature>/requirements.md` — единственный авторский документ. Обвязка не формирует:

- срезы;
- отдельные требования клиентской и серверной частей;
- предварительные задачи разработки;
- копии требований после каждого изменения.

## Передача

По явной команде передачи обвязка:

1. проверяет корневой документ;
2. исправляет только однозначные ошибки;
3. задаёт по одному вопросу для каждого предметного сомнения;
4. копирует текущий `requirements.md` в неизменяемую редакцию;
5. создаёт или обновляет `manifest.json`;
6. выбирает существующий доступный `requirements-exchange/` в кодовом репозитории либо резервный каталог с тем же именем в аналитическом репозитории;
7. сообщает фактическое место размещения.

Форматы манифеста и возвратов находятся в `templates/exchange/`.
