# Аналитическая проверка возврата разработки

Это собственный разбор аналитической стороны, не замена исходного returns и не
принятое решение. Заполняй по core/developer-handoff.md. Вопросы, доступные
проверке по коду, сначала исследуй самостоятельно.

## Идентичность и источники

- Поставка, квартал, этап, редакция:
- return_id (если подтверждён штатным scan), путь и контрольная сумма возврата:
- Манифест, входные requirements и SHA-256; SDD-профиль и контрольные суммы:
- Сравнение с текущим авторским документом:
- Репозиторий и полный SHA из отчёта:
- Исследуемая версия: репозиторий, ветка/локальный ref, полный SHA, чистота:
- Связь версий и последующие изменения затронутых участков:
- Свежесть версии, недоступные источники и ограничения:
- Свидетельство штатных begin/verify и неизменности code:

## Пользовательская цепочка

<Источники → обработка → API/связанные данные → клиент → результат.

## Доказательства по каждому сценарию

Повтори строку для каждого сценария каждого входного REQ. Отсутствие реализации,
отличие и недостаток доказательств различаются. Не превращай наличие теста в
успешный прогон. Не выводи отсутствие поведения только из отсутствия поля/строки.

| REQ и заголовок сценария | Ожидается во входе | Утверждение возврата | Факт по коду и версия | Доказательство: путь/символ/строки | Вид проверки и фактический результат | Отличие и пользовательское последствие | Недостающие доказательства |
|---|---|---|---|---|---|---|---|

## Кандидаты решений

Для каждого различия предложи рекомендацию и применимые альтернативы, включая
сохранение реализации с изменением требований. Выбор поведения отделяй от сроков.
Здесь не создаются tracker-задачи и не назначаются спринты.

| REQ/сценарии | Рекомендуемое целевое поведение | Альтернативы и последствия | Остаток и зависимости | Решение аналитика: точная формулировка и источник либо «не принято» | Подтверждённое размещение/срок либо «не выбраны» |
|---|---|---|---|---|---|
| | | | | | |

## Только недоступные доказательства

<Что уже проверено; какой точный пробел остался; почему нельзя закрыть локально;
у кого/в какой среде есть источник; какое решение блокируется; какая независимая
работа продолжается. Если пробелов нет — «нет». Сводный запрос разработке
отправляется только с разрешения аналитика; исходный отчёт не переписывается.>
