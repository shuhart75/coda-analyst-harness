# Обмен требованиями и результатами разработки

Версия договора: `3`

Каталог связывает требования аналитиков с фактической работой разработчиков.

Для каждой функциональности входом служат только:

- `manifest.json`;
- одна активная редакция `revisions/<NNN>/requirements.md`.

Разработческая SDD читает формальный договор из `AGENTS.md`. При первом принятии
редакции она создаёт `revisions/<NNN>/returns/receipt.json` по корневому
`receipt.template.json`, а затем записывает остальные результаты в тот же `returns/`.

Переданный `requirements.md` является бизнес-контрактом, а не готовым техническим
`spec.md`. Разработческая SDD сверяет его с актуальным кодом и создаёт собственные
технические спецификации, решения и задачи в локальном процессе каждого затронутого
контура.

Входные редакции требований неизменяемы. Новые вводные передаются новой редакцией. Возвраты одной редакции не переносятся в другую автоматически.

Файл `returns/tasks.md` содержит уже согласованную разработчиками разбивку. Аналитическая сторона не участвует в её согласовании и не подтверждает её.

Состояние обработки определяется по файлам активной редакции:

- нет `receipt.json` — новая редакция ещё не принята;
- есть только квитанция — редакция принята, идёт сверка с кодом;
- появился `tasks.md` — согласованная декомпозиция записана;
- появились `tasks/<task-id>.md` — реализация выполняется;
- появился полный `summary.md` — редакция обработана.

Каждая новая редакция требует собственной квитанции. Результаты прежней редакции
не означают, что новая редакция уже принята или обработана.
