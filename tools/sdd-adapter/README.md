# Подключение SDD Orchestrator

Обвязка закрепляет конкретный коммит самостоятельного проекта в
`runtime-lock.json`. Обычный запуск не скачивает код и не обновляет версию.

После обновления обвязки установите закреплённую версию под своим пользователем:

```sh
python3 tools/sdd-adapter/install.py
```

Нужны Python и Git с доступом к приватному репозиторию
`shuhart75/sdd-orchestrator`. Node.js, pnpm и права администратора не нужны.
Сохранённые прогоны и работающие сервисы установщик не изменяет.

Если репозиторий уже клонирован или используется другой Git-транспорт:

```sh
python3 tools/sdd-adapter/install.py --source /путь/к/sdd-orchestrator
python3 tools/sdd-adapter/install.py --source git@github.com:shuhart75/sdd-orchestrator.git
```

Источник должен содержать именно закреплённый коммит. Установщик создаёт свою
чистую копию и не меняет исходный checkout. После проверки новая копия атомарно
появляется в пользовательском каталоге версий. Неудачная установка не заменяет
предыдущую версию. Повторная установка проверяет уже имеющуюся копию.

На macOS версии хранятся в `~/Library/Application Support/sdd-orchestrator/versions`,
на Linux в `${XDG_DATA_HOME:-~/.local/share}/sdd-orchestrator/versions`,
на Windows в `%LOCALAPPDATA%/sdd-orchestrator/versions`.

`SDD_ORCHESTRATOR_CACHE` задаёт другой пользовательский каталог версий.
`SDD_ORCHESTRATOR_HOME` указывает готовый отдельный Git-checkout; он тоже обязан
соответствовать закреплённому коммиту и иметь неизменённые отслеживаемые файлы.
Незарегистрированные исполняемые модули запрещены, обычные файлы диагностики
не мешают запуску. Python запускается без внешнего `PYTHONPATH`, пользовательского
site-packages и с отдельным каталогом байткода.

При отсутствующей или другой версии адаптер выводит команду установки и
завершается, не меняя состояние прогона. Старые точки входа обвязки передают
аргументы оркестратору без преобразования и сохраняют текущий рабочий каталог.
