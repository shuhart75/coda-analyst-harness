# Независимое ревью плана двумя моделями

Эксперимент запускает только проверку одного сохранённого кандидата плана.
Он не запускает планировщика, исполнителей или стенд, не принимает план и не
переносит результаты в основной state. Зависимости не устанавливаются.

На Mac с уже установленной обвязкой:

```bash
python3 "$HOME/Documents/coda-analyst-harness/tools/gigacode-sdd/compare_plan_models.py"
```

Последний запуск определяется через `last-run.json`. Исходный runner должен быть
остановлен. Скрипт удерживает его `run.lock` на время эксперимента, проверяет
сохранившиеся процессы и слушающие сервисы в каталоге запуска. Обычные сервисы
вне него не останавливаются. Для другого запуска можно передать
`--config /полный/путь/config.json`.

Используются два независимых CLI-процесса с `--approval-mode plan` и явным
`--model`: `DeepSeek-V4.1-Flash-1017` и `GLM-5.3-Flash`. Это кандидаты на
идентификаторы из интерфейса, а не заранее проверенные значения CLI.
Для других идентификаторов есть `--deepseek-model` и `--glm-model`.
Fallback не задаётся. Effort не задаётся: соответствующая опция не подтверждена.

Если CLI не сообщает модель в метаданных событий, идентичность отмечается как
неподтверждённая. Если сообщает другой идентификатор, это отражается как
несовпадение или неразрешённый alias. Неизвестный идентификатор не заменяется
автоматически. Самоописание модели в тексте ответа не считается метаданными.

Каждая модель получает отдельную копию одного кода и одинаковые требования,
кандидат плана и `decision.md` под `.review-input/`. Контрольные суммы проверяются
до запуска и после завершения. Задание одинаковое. Смотреть другие каталоги,
использовать shell, субагентов или менять файлы запрещено заданием; включён
режим plan. Это не отдельная ОС-песочница. Вызов shell, инструмента записи, субагента или изменение копии
помечает сравнение как неконтролируемое. Модель субагента не выводится из модели
основной сессии. Проверка процессов по cwd не обнаруживает все возможные
отсоединённые процессы за пределами копии.

Ожидание выводится каждые 30 секунд: число полученных событий, вызовов инструментов,
результатов и давность последнего полученного события. Это активность журнала,
а не доказательство продвижения по требованиям. Ограничение каждой сессии:
20 минут; меняется через `--timeout` (секунды). `Ctrl+C` один раз запрашивает
остановку обеих сессий; группы с сервисами или неполной диагностикой сохраняются
для разбора, не завершаются принудительно.

Результаты находятся в `~/Library/Application Support/GigaCode SDD/experiments/`:

- `manifest.json`, `effective-input.json`: вход, контрольные суммы, запрошенные модели.
- `deepseek/session/` и `glm/session/`: исходные prompt, stdout.jsonl, stderr.log.
- `deepseek/result.json` и `glm/result.json`: время, метаданные модели, ошибки,
  вердикт, находки, ссылки на доказательства и ограничения.
- `comparison.json`: точные текстовые совпадения, несовпадающие формулировки,
  группы по требованиям для проверки смысловых совпадений и противоречий.
- `comparison-redacted.json`: версия сравнения с эвристическим скрытием секретов.

Сырые журналы приватны и могут содержать чувствительные данные. Эвристическое
скрытие не гарантирует удаления всех секретов. Перед передачей отчёт проверяют.
Совпадение текста не подтверждает дефект; разная формулировка не доказывает
уникальность. Семантические совпадения и противоречия проверяются по приведённым
ссылкам на код и требования после получения обоих результатов. Скорость,
совпавший вердикт и большинство голосов не заменяют эту проверку.

Код возврата 0 означает две завершённые сессии с подтверждёнными точными
идентификаторами, корректными отчётами и неизменными входами. Это не приёмка PoC
или плана. Код 2 означает ошибку или ограничение сравнения; сохранённые отчёты
остаются пригодны для ручного разбора с указанными ограничениями.

Если модель добавила вводную фразу перед единственным JSON-блоком, отчёт можно
извлечь без повторного API-вызова:

```bash
python3 compare_plan_models.py --recover "/полный/путь/к/experiments/plan-review-ДАТА-ID"
```

Будет создан новый каталог `recovered-*`. Исходные журналы, результаты и основной
state не меняются. Ошибки инструментов и ограничения идентичности моделей
сохраняются. Успешное извлечение JSON не делает сессию безошибочной. Несколько
JSON-блоков или повреждённый JSON автоматически не исправляются.

## Импорт исправленного кандидата

После предметной проверки можно импортировать локальный исправленный JSON без
повторной генерации плана. Runner должен быть остановлен, состояние initialized,
задачи исполнителей ещё не созданы:

```bash
python3 tools/gigacode-sdd/import_plan.py --plan /путь/plan-corrected.json --expected-sha256 SHA256_ИСХОДНОГО_КАНДИДАТА
```

Последний запуск определяется через last-run.json; можно передать --config.
Проверяются блокировка запуска, сохранённые процессы, закреплённый вход,
исходный SHA, метаданные кандидата и структура исправленного плана. Импорт
сохраняет прежний план и state в plan-imports/, пишет новый кандидат отдельным
файлом и атомарно переключает указатель state. Preflight не сбрасывается.
Импорт не принимает план и не запускает модель. Затем обычное продолжение через
bootstrap.py передаёт кандидат на независимое ревью без вызова планировщика.
После замечаний или ошибки ревью запуск останавливается до импорта исправленного кандидата.
Повторный bootstrap не запускает новый цикл автоматически; автоматического pass нет.
Старые файлы кандидатов сохраняются для диагностики.

Ревью плана в основном runner получает локальный `.review-input/plan.json` и
копию закреплённого пакета. Ответ обязан содержать SHA-256 этого кандидата.
Журнал вызовов проверяется: чтение за пределами копии, субагенты и неизвестные
shell-команды делают результат непригодным для принятия плана. В основном runner
два точных литерала `true` и `echo no` игнорируются без отдельной диагностики
и не отклоняют ревью. Перенаправления, составные команды, подстановки
и дополнительные аргументы инструмента не допускаются этим исключением.
Исходный stdout.jsonl сохраняется без изменений. Ошибки CLI,
нарушения прав, изменение копии и неверный SHA по-прежнему блокируют принятие.
Эксперимент сравнения моделей сохраняет собственную строгую оценку протокола. Это проверка результата после
сессии, а не отдельная ОС-песочница. Старые планы не удаляются, но не являются
входом ревью. При остановке checkpoint и кандидат сохраняются.
